## 0. Summary of decisions

| # | Area | Decision for the initial implementation |
|---|---|---|
| A | Framework | **axum** on tokio + `tower-http` middleware |
| B | API | REST `/api/v1`, a raw streaming upload body (not multipart), owner-scoped resources, one error envelope reusing the existing error-code vocabulary |
| C | Jobs | In-memory owner-scoped job store, server UUIDv4 IDs, explicit state machine with `cancelling`, retry creates a **new** job, per-class semaphores, and no automatic retry |
| D | Storage | A single exclusive `DATA_ROOT` on a dedicated volume. Per-user directories are keyed by an HMAC of `(tenant, user)`. Paths are built only from typed IDs and fixed literals, with TTL cleanup and a full purge on startup (safe because one instance holds an exclusive lock) |

| F | Multi-user | Ownership lives only in server records. Handlers can only reach a resource through `store.get_owned(&user, id)`, and every foreign or unknown ID returns **404** |

| H | Upload/download | Streaming with a byte cap. Type is decided by server sniffing (client MIME ignored), the extension must agree with the sniffed type, names are generated by the server, and downloads use `attachment` + `nosniff` + sandbox CSP |

## A. WEB FRAMEWORK

**Recommended: axum** (the current stable 0.x release at implementation time), with `tower-http` for `RequestBodyLimitLayer`, `TimeoutLayer`, `TraceLayer`, `SetResponseHeaderLayer` and `ServeDir`.

**Why**
- `tokio` (`features = ["full"]`) is already a dependency in `src-tauri/Cargo.toml`, so axum adds no second runtime.
- It has built-in SSE (`axum::response::sse`) with keep-alive. That is the recommended progress channel (§G).
- Request bodies can be read as a `Stream`, so uploads go straight to disk with a byte counter (§H) and are never buffered in memory.
- Tower layers map one-to-one onto the controls this design needs: body limits, per-route timeouts, the auth layer and security headers.
- Extractors make the `AuthenticatedUser` requirement type-checked. A handler that does not take `AuthenticatedUser` cannot be added to the protected router (§F).

**Alternatives considered**

| Option | Reason not chosen |
|---|---|
| actix-web | Mature and fast. However, it has its own runtime model (actix-rt), integrates less naturally with the existing tokio code and `spawn_blocking` patterns, and gives no advantage here |
| rocket | Ergonomic, but its middleware and streaming-body ecosystem is thinner. Upload streaming and SSE need more custom code |
| poem / salvo | Viable, but smaller communities, which is a long-term maintenance risk for an institutional product |
| warp | Little ongoing development compared with axum. Filter-based composition gets hard to read at this scale |

**Migration impact.** Each existing `#[tauri::command]` becomes an axum handler that calls the same inner function. All of these are reused unchanged: `ConversionResult`, `Capability`, `SpeechErrorDto`, `TranscriptDto`, `JobUpdate` and the serde derives. Blocking engine work stays on `tokio::task::spawn_blocking` or dedicated worker threads, the same pattern `speech/commands.rs` already uses via `tauri::async_runtime::spawn_blocking`.

**Risks**
- axum 0.x releases can break APIs. Pin the minor version and upgrade deliberately.
- axum's `DefaultBodyLimit` (2 MB) must be disabled **only** on the upload route and replaced by our own streaming cap.
- Accidentally blocking the async runtime. Rule: no engine or file-system-heavy call runs inside a handler; jobs run on workers.

## B. API MODEL

### B.1 Conventions
- **Base path:** `/api/v1`. Bodies are JSON (`application/json`), except the upload body and download responses.
- **Authentication:** every route needs it except `/healthz` and `/readyz` (§J).
- **IDs:** all IDs are server-generated UUIDv4 strings. Unknown, foreign, expired and malformed IDs all return **404 `NOT_FOUND`**, with identical bodies and timing class.
- **State-changing requests** (`POST`/`DELETE`) must send the header `X-MEB-Request: 1`, and `Origin` must match the configured public origin. This is the CSRF guard needed if auth is cookie-based at the proxy.
- **Error envelope**, reusing the existing code vocabulary (`EngineError::code()`, `SpeechErrorCode`, the image error kinds):
  ```json
  { "error": { "code": "OFFICE_TIMEOUT", "message": "<Türkçe kullanıcı mesajı>", "request_id": "4f0c…" } }
  ```
  Raw tool stderr and filesystem paths never appear in responses. This extends the `EngineError::Display` discipline to everything and replaces the legacy `"{cmd} failed:\nStderr:…"` strings in `converter.rs`.
- **Time and sizes:** times are RFC 3339 UTC; sizes are bytes as `u64`.

### B.2 Endpoints

#### `GET /api/v1/capabilities`
Purpose: report what this server can do now, plus the limits that apply to this user.

```json
{
  "capabilities": [ { "id": "office_to_pdf", "state": "AVAILABLE", "message": "…" }, … ],
  "limits": {
    "max_upload_bytes": { "image": 52428800, "document": 104857600, "pdf": 209715200, "audio": 524288000, "video": 2147483648, "archive": 524288000 },
    "max_parallel_jobs": 2, "max_queued_jobs": 20,
    "speech": { "max_audio_secs": 10800, "max_recording_secs": 7200 },
    "user_quota_bytes": 2147483648
  },
  "formats": { "pdf": ["docx","odt","rtf","txt","png","jpg"], "docx": ["pdf","odt","rtf","txt","html"], … }
}
```
- Capabilities come from `capabilities::compute_capabilities()`, which is reused. Results are cached for 60 s because the speech self-check hashes the model. New ids: `pdf_to_docx` (§N), `image_optimization` (§Q), and later `sas_*` (§P).
- `formats` comes from the server's own matrix (`tools::get_supported_output_formats`, moved), intersected with the capabilities that are `AVAILABLE`. The client may only offer what this lists.
- Errors: `401`.

#### `POST /api/v1/files` — upload
- **Request:** the body is the raw file bytes (`Content-Type` is ignored for decisions). Headers:
  - `X-File-Name: <percent-encoded original name>` (required, display only)
  - `X-Upload-Purpose: convert | speech | speech_recording` (optional; selects which allow-list applies)
  - `Content-Length` (required; chunked uploads are refused)
- **Response:** `201`
  ```json
  { "file_id": "…", "display_name": "rapor.docx", "size": 482113,
    "detected": { "family": "document", "format": "docx" },
    "probe": { "pages": null, "duration_secs": null, "width": null, "height": null },
    "expires_at": "2026-10-01T12:00:00Z" }
  ```
- **Validation:** see §H. All of these happen before a `201` is returned: byte cap while streaming, sniff, extension/sniff agreement, structural probe, quota check.
- **Errors:**

  | Status | Code |
  |---|---|
  | 400 | `MISSING_FILE_NAME` |
  | 411 | `LENGTH_REQUIRED` |
  | 413 | `UPLOAD_TOO_LARGE` |
  | 415 | `UNSUPPORTED_FILE_TYPE` |
  | 422 | `FILE_TYPE_MISMATCH`, `FILE_CORRUPT`, `IMAGE_TOO_LARGE` (existing native limit), `SPEECH_RESOURCE_LIMIT` (existing) |
  | 429 | `USER_QUOTA_EXCEEDED`, `RATE_LIMITED` |
  | 507 | `SERVER_STORAGE_FULL` |

#### `GET /api/v1/files/:id`
Returns the same metadata object as the upload response. It **never returns content**: there is no download of an original, because the user already has it. Errors: `404`.

#### `DELETE /api/v1/files/:id` (added)
Deletes an uploaded file immediately. If queued or running jobs reference it, the server answers `409 FILE_IN_USE`; cancel those jobs first. Success is `204`.

#### `POST /api/v1/jobs`
```json
{ "kind": "convert", "file_id": "…", "output_format": "pdf",
  "options": { "quality": 85, "width": null, "height": null, "preserve_metadata": false } }
```
- **Kinds in v1:**

  | Kind | Purpose | Source |
  |---|---|---|
  | `convert` | General conversion | `converter::convert_file` |
  | `video_trim` | Trim a video | `trim_video_helper` |
  | `speech_transcribe` | Transcribe audio | `speech/pipeline.rs` |
  | `archive_bundle` | Zip several *outputs* for one download | NEW |

  Later kinds: `image_optimize`, `pdf_text_edit`, `data_convert`, `ocr`.
- **`options`** is a typed struct per kind with `#[serde(deny_unknown_fields)]` and range-checked values. Settings the frontend sends today that are **refused**: `custom_ffmpeg_params`, `use_gpu`, `gpu_encoder` and `two_pass`. Hardware and encoder choice is server policy.
- **Response:** `202 { "job_id": "…", "state": "queued", "queue_position": 3 }`
- **Validation:**
  - The file is owned by the caller and not expired.
  - `(detected.format, output_format)` is in the matrix.
  - The capability is `AVAILABLE`. The server enforces what `capabilityGating.ts` only enforces "defence in depth" today.
  - The per-user queue limit is respected.
- **Errors:**

  | Status | Code |
  |---|---|
  | 400 | `INVALID_REQUEST` |
  | 404 | (file) |
  | 422 | `UNSUPPORTED_CONVERSION`, `FEATURE_NOT_IMPLEMENTED`, `ENGINE_MISSING` |
  | 429 | `TOO_MANY_JOBS` |
  | 503 | `QUEUE_FULL` (with `Retry-After`) |

#### `GET /api/v1/jobs/:id`
Snapshot, and the source of truth after a reconnect:
```json
{ "job_id": "…", "kind": "convert", "state": "running", "stage": "converting",
  "progress_pct": 42, "eta_secs": 31, "elapsed_secs": 12, "queue_position": null,
  "file_id": "…", "retry_of": null,
  "result": null, "error": null, "created_at": "…", "expires_at": "…" }
```
When the job completes, `result` holds `{ "output_name": "rapor.pdf", "size": 120331, "content_type": "application/pdf" }`. For speech it holds `{ "transcript_available": true, "timestamps_available": true, "language": "tr" }`. Errors: `404`.

#### `GET /api/v1/jobs/:id/events`
SSE for one job (the event format is in §G). Use it for single-job screens. Errors: `404`.

#### `GET /api/v1/events` (added)
**Per-user multiplexed SSE.** Carries every job event for the caller and is the stream the main UI uses (§G).

#### `POST /api/v1/jobs/:id/cancel`
Idempotent. Returns `202 { "state": "cancelling" | "cancelled" }`. If the job is already terminal, it returns `200` with the current state. Errors: `404`.

#### `POST /api/v1/jobs/:id/retry`
Returns `202 { "job_id": "<new>", "retry_of": "<old>" }`. Rules are in §C.6. Errors: `404`, `409 NOT_RETRYABLE`, `410 SOURCE_EXPIRED`, `429 RETRY_LIMIT`.

#### `GET /api/v1/jobs/:id/download`
Streams the output. It requires `state == completed`. For `speech_transcribe` jobs, `?format=txt|srt|vtt|json` (default `txt`) renders on demand from the stored `transcript.json`. Headers are in §H.5. Errors: `404`, `409 NOT_READY`, `410 EXPIRED`.

#### `GET /api/v1/jobs/:id/transcript` (added, speech only)
Returns the `TranscriptDto` as JSON, the shape `speech/commands.rs` already defines:
```json
{ "language": "tr", "text": "…", "timestamps_available": true,
  "segments": [ { "start_ms": 0, "end_ms": 2310, "text": "…" } ] }
```

#### `DELETE /api/v1/jobs/:id`
Cancels the job if active, then purges its workspace and record immediately. Returns `204`. Later requests for that ID get `404`.

#### `GET /api/v1/privacy-status` (added)
Replaces `system_status`. The values are re-stated honestly for a server (§S.4).

#### `GET /healthz`, `GET /readyz` (added)
Unauthenticated, bound to the internal interface or filtered by the proxy.
- `healthz` reports that the process is alive.
- `readyz` reports that the data root is writable, the free-space watermark is OK and the engine manifests are verified.

### B.3 Speech / dictation flow

```
[file]        POST /files  (X-Upload-Purpose: speech)            → file_id
[microphone]  MediaRecorder … stop → POST /files (X-Upload-Purpose: speech_recording) → file_id
              POST /jobs { kind: "speech_transcribe", file_id, options: { language: "tr" } } → job_id
              SSE events: preparing → transcribing (progress_pct from whisper, else null) → completed
              GET /jobs/:id/transcript                → JSON segments (UI)
              GET /jobs/:id/download?format=srt|txt   → export
              POST /jobs/:id/cancel  /  DELETE /jobs/:id
```
The old pre-start inspection call (`speech_inspect_file`) is folded into the upload probe: duration and the limit check run there.

## C. JOB MODEL

### C.1 Identifiers
| ID | Generation | Notes |
|---|---|---|
| `file_id`, `job_id` | `uuid::Uuid::new_v4()` (CSPRNG; the `uuid` crate is already a dependency), on the server only | Newtypes `FileId(Uuid)` and `JobId(Uuid)`. Parsed from the URL with `Uuid::parse_str`. A string that fails to parse is a 404 and never reaches storage |
| `request_id` | UUIDv4 per HTTP request | Logs and error envelopes |
| `user_key` | `hex(HMAC-SHA256(server_secret, tenant_id ‖ 0x00 ‖ user_id))[..32]` | Used for directory names and logs. Not reversible without the secret. Uses `sha2`, already a dependency, plus `hmac` (**NEW** dependency) |

This reverses today's model, where the **frontend** picks the job id (`useStore.convertFiles` passes `jobId: file.id`) and `CANCELLED_JOBS` trusts it.

### C.2 Ownership
Each `FileRecord` and `JobRecord` holds an `owner: OwnerRef { tenant_id, user_id, user_key }`, copied **only** from the `AuthenticatedUser` of the creating request.
- A job may only reference files with the same `OwnerRef`.
- The workspace (§D) is derived from the job's owner, so the physical location mirrors logical ownership.

### C.3 States

```
            ┌──────────── cancel ────────────┐
queued ──► preparing ──► running ──► finalizing ──► completed ──(TTL)──► expired
  │            │            │            │
  │            └──── error ─┴────────────┴──► failed ──(TTL)──► expired
  └─ cancel ─► cancelled          running/preparing ─ cancel ─► cancelling ─► cancelled ─(TTL)─► expired
```

| State | Meaning |
|---|---|
| `queued` | Accepted and waiting for a class permit. It holds a queue position |
| `preparing` | Workspace is created, input is staged, the engine is resolved and probed |
| `running` | The engine is executing. Progress is reported if the engine provides it |
| `finalizing` | Output validation (§H.4) and the move into `out/` |
| `completed` | Output is available until `expires_at` |
| `failed` | Terminal, with `error.code` |
| `cancelling` | Cancel accepted; the process tree is being killed. Transient, normally under 2 s |
| `cancelled` | Terminal. No output is ever kept |
| `expired` | The record is still visible briefly as a tombstone (until the next janitor pass), then deleted, after which the ID returns 404 |

Terminal states are immutable. This maps onto the existing speech `JobState` (`Preparing`, `Transcribing`→`running`, `Completed`, `Cancelled`, `Failed`) and the frontend's `ConversionFile.status`.

### C.4 Queue behaviour
- **Per-class FIFO queues:**

  | Class | Kinds |
  |---|---|
  | `light` | native image, ZIP bundle, image optimise |
  | `office` | LibreOffice |
  | `media` | FFmpeg video/audio |
  | `speech` | whisper |
  | `data` | SAS, later |

  Each class has a `tokio::sync::Semaphore` with the capacity from §I.
- **Fairness:** a job is admitted only if the owner has fewer than `max_running_per_user` running jobs. If not, it stays queued and the scheduler takes the next job from a different user (per-class round-robin over users). This stops one user's batch of 50 files from starving everyone else.
- **Bounds:** the per-user queue limit (`max_queued_per_user`) and the global queue limit (`max_queued_global`) are enforced at `POST /jobs`, not after.
- **Restarts:** queues are not persisted. A server restart fails every non-terminal job with `SERVER_RESTARTED` (§D.7).

### C.5 Worker behaviour
- A worker task acquires the class permit, then runs the job body on `spawn_blocking`. The body is the existing synchronous engine code: `converter` functions, `speech::pipeline::run_file_job_in`, and so on.
- The body receives a **NEW** `JobContext` (defined in `meb-core`):
  - `workspace: &Workspace`
  - `cancel: &CancelToken` (wraps `Arc<AtomicBool>`, the type `speech/job.rs` and `process::CancellableRun` already use)
  - `progress: &dyn ProgressSink` (replaces `converter::APP_HANDLE.emit` and the speech `app.emit`)
  - `limits: &JobLimits`
- **Panics:** the server profile uses `panic = "unwind"`, unlike the current release profile's `panic = "abort"`. The job body runs inside `std::panic::catch_unwind`, and a panic becomes `failed / INTERNAL_ERROR` for that job only.
- The worker always ends by dropping the workspace guard, which cleans up on every path. This is the same Drop discipline as `JobTempDir` and `SpeechJobDir`.

### C.6 Retry semantics
- Only `failed` or `cancelled` jobs can be retried. A `completed` job cannot, because the user creates a new job instead.
- Retry creates a **new** `job_id` with `retry_of = old_id`, the same `file_id`, kind and options. The old record is never mutated.
- The source file must still exist. Files are retained while any job references them, plus `upload_ttl`; if gone, the answer is `410 SOURCE_EXPIRED`.
- A lineage allows at most 3 retries (`429 RETRY_LIMIT`).
- There is **no automatic server-side retry**. Conversions are deterministic, so automatic retry would only multiply load from hostile inputs.
- The frontend "Yeniden dene" button (`useStore.retryFile`, the speech page) maps to this endpoint.

### C.7 Cancellation semantics
| State at cancel | Effect |
|---|---|
| `queued` | Removed from the queue, then `cancelled` immediately |
| `preparing` / `running` | The state becomes `cancelling` and `CancelToken` is set. The executor (§E) kills the **process tree** within its poll interval (50 ms, as in `run_cancellable`). The worker sees `ProcessEnd::Cancelled` and the workspace is purged. The job becomes `cancelled` |
| In-process engines (native image, ZIP, lopdf) | They check the token between stages (decode → transform → encode; per archive entry). Their bounded runtime comes from the pixel and entry caps |
| `finalizing` | Cancel is honoured if the output has not yet been published to `out/`; otherwise the job completes |
| Terminal | No-op |

This fixes Audit §0.4: Office jobs become cancellable because `engines::office::convert` gets the token.

### C.8 Progress model
```rust
// NEW, meb-core
pub struct ProgressEvent { pub stage: Stage, pub pct: Option<u8>, pub eta_secs: Option<u32>, pub speed: Option<f32> }
pub enum Stage { Queued, Preparing, Converting, Transcribing, Finalizing }
```
- **Real values only.** `pct` is `None` unless the engine reports it, keeping the rule already enforced in `useSpeechJob.ts` and `speech/pipeline.rs` ("never invented").
- **Sources:**
  - FFmpeg `time=` / `speed=` parsing, from `converter::parse_ffmpeg_time` and `parse_ffmpeg_speed`
  - whisper `progress = NN%`, from `speech::parse_progress`
  - native image stage steps (0 → 33 → 66 → 100)
  - LibreOffice gives none, so the UI shows an indeterminate state with elapsed time
- **Delivery:** the server adds `seq` (a monotonic per-job counter), `elapsed_secs` and `state`, and publishes to the event bus (§G). A 1 Hz ticker, the existing speech pattern, refreshes `elapsed_secs` for jobs with no progress.

### C.9 Cleanup semantics
| Trigger | Action |
|---|---|
| Job ends `failed` or `cancelled` | Workspace purged immediately (`in/`, `work/`, `out/`); record kept until `job_record_ttl` |
| Job `completed` | `in/` and `work/` purged immediately. `out/` kept until `output_ttl`, or until `delete_after_download` fires if enabled |
| Upload not used by any job | Deleted after `upload_ttl` |
| `DELETE` endpoints | Immediate purge |
| Janitor (every 60 s) | Enforces TTLs and the free-space watermark (evicting the oldest `completed` outputs first) |
| Startup / shutdown | §D.7 |

## D. STORAGE

### D.1 Layout (chosen)

```
<DATA_ROOT>/                         dedicated volume; owned by the service account only
  .instance.lock                     exclusive lock held for the server's lifetime
  staging/                           in-flight uploads (not yet validated)
    <upload-uuid>.part
  users/
    <user_key>/                      32 hex chars (HMAC, §C.1); created on first upload
      files/
        <file_id>/
          blob                       validated upload; server-generated fixed name, no extension
      jobs/
        <job_id>/
          in/   source.<ext>         hard link (or copy) of files/<file_id>/blob; <ext> from sniffed type
          work/                      engine cwd; LibreOffice profile, ffmpeg temp, whisper JSON, TMP/HOME
          out/  result.<ext>         only validated output is ever placed here
```

**Why this shape rather than the example in the brief**
- `staging/` sits outside `users/`. An unvalidated upload can never appear under a user's tree, and a disconnect leaves debris only in one place the janitor wipes.
- `files/` is separate from `jobs/`. One upload can feed several jobs (retry, different target formats) without re-uploading, and deleting a job never deletes the user's source.
- Fixed names (`blob`, `source.<ext>`, `result.<ext>`) mean user-supplied text never forms any path component. The display name lives only in memory (`FileRecord.display_name`). The speech pipeline already does this (`input.<ext>` in `pipeline.rs`), and this design generalises it.
- `<user_key>` is opaque. Directory listings or backup logs never reveal identities, and the key cannot contain separators.
- `work/` is distinct from `out/`. An engine can only write into `work/`; publishing to `out/` is a separate, validated step (§H.4), which generalises `confirm_within` and `move_into_place`.

### D.2 Path construction and canonicalisation
- **NEW** `storage::layout` has functions that take **only** typed values: `fn job_dir(&self, owner: &OwnerRef, id: JobId) -> PathBuf`. It joins `DATA_ROOT` (canonicalised once at startup), literal segments and `Uuid::to_string()`/hex output. No function accepts a `&str` from a request.
- On startup, `DATA_ROOT` is canonicalised, checked to be a directory, checked to be **not** inside `ENGINES_ROOT` or the binary's directory (the `is_within_app_directory` idea from `path_validation.rs`), and checked to be writable.
- After an engine runs, every produced path is checked with `symlink_metadata` and `canonicalize`, then `starts_with(job.work)`, before use. This keeps the existing `path_validation::confirm_within`.
- On Windows, the `\\?\` prefix normalisation from `path_validation::normalize_windows_prefix` is kept for LibreOffice arguments.
- `DATA_ROOT` and `ENGINES_ROOT` must be **pure ASCII**, which is checked at startup. `engines::speech` then passes the absolute model path directly, as `ascii_link::expose_model` already does for ASCII paths. Junction creation is no longer needed and `ascii_link` stays only as a fallback.

### D.3 Permissions
**Windows (pilot):**
- `DATA_ROOT` ACL: full control for the service's virtual account (`NT SERVICE\MebDonustur`) and SYSTEM; Administrators get read only (or none, per policy). Inheritance is disabled at the root.
- `ENGINES_ROOT`: read and execute for the service account; no write access.

**Linux (later):**
- `DATA_ROOT` mode `0700` owned by the `meb` user, mounted `nodev,nosuid,noexec`. Files are created with `0600`.
- `ENGINES_ROOT` is root-owned with mode `0755`.

### D.4 Symlink and reparse-point handling
- Files are created with `OpenOptions::create_new(true)`, so an existing name, including a planted link, is never followed or overwritten.
- Before reading any engine output, `symlink_metadata().file_type().is_file()` must be true. Links, junctions, directories and devices are rejected.
  - Windows: also reject `FILE_ATTRIBUTE_REPARSE_POINT`.
  - Linux: open outputs with `O_NOFOLLOW` (`OpenOptionsExt::custom_flags`).
- Workspaces are deleted with `std::fs::remove_dir_all`. Since Rust 1.58.1 (CVE-2022-21658) it does not follow symlinks out of the tree. This means the crate's `rust-version = "1.70"` floor is already safe, and the server crate will require a newer version anyway.
- The archive extractor never creates links (§O).

### D.5 Quotas
| Quota | Default |
|---|---|
| Per user | `user_quota_bytes` = 2 GiB, counting `files/` + `jobs/*/out/` + `staging/` in flight. Tracked as an in-memory counter, updated on create/delete and re-measured by the janitor |
| Global free-space watermark | Refuse new uploads and jobs (`507`) when free space < max(10 % of the volume, 20 GiB). `readyz` reports not ready |
| Pre-flight | Before a job starts, check the estimated workspace need. Generalises `SpeechLimits::required_disk_bytes`; `limits::free_disk_bytes` must gain a non-Windows implementation via `statvfs`, **NEW** |

### D.6 Retention (initial defaults)
| Item | Default | Rationale |
|---|---|---|
| `upload_ttl` (unused upload) | 60 min | Enough for "upload, pick format, convert" |
| `output_ttl` (completed output) | 60 min after completion | No user-visible history is required |
| `delete_after_download` | **on**, with a 5-minute grace period (for a re-click or browser retry) | Smallest exposure window |
| `job_record_ttl` (terminal record) | Same as the output; then 404 | No history |
| Transcript | Same as `output_ttl` | Sensitive text |

### D.7 Cleanup and stale-job recovery
- **Single instance:** the server takes an exclusive OS lock on `.instance.lock` (`LockFileEx` / `flock`) before doing anything. If the lock is held, it refuses to start. This turns Audit H7 (the startup sweep deleting another instance's jobs) into a guaranteed invariant instead of a hazard.
- **Startup:** because no job records are persisted and this process is the sole owner, the startup purge deletes `staging/*` and every `users/*/jobs/*` and `users/*/files/*`. Users with jobs in flight see `SERVER_RESTARTED`, because the SPA re-fetches snapshots and gets 404. This replaces `security::temp::cleanup_stale_job_dirs` and `speech::job::cleanup_stale_speech_dirs`, and also the never-cleaned `localconvert_archive_<ms>` path.
- **Graceful shutdown (SIGTERM / service stop):**
  1. Stop accepting requests (axum `with_graceful_shutdown`).
  2. Set every `CancelToken`.
  3. Wait up to 10 s.
  4. Close Job Objects / kill process groups.
  5. Purge.
- **Horizontal scaling (more than one instance)** is explicitly out of scope for v1. It would need shared job state, and the lock design makes the limitation visible rather than silently unsafe.

## E. PROCESS EXECUTION

### E.1 One executor
**NEW** `meb-core::exec`, evolved from `src-tauri/src/engines/process.rs`, whose invariants it keeps: no shell, argument arrays, the executable comes only from the resolver, cwd is the job directory, both pipes are drained on threads, the cancel flag is polled, and the child is killed and reaped.

The legacy launchers are **deleted**:
- `converter::run_command`
- `converter::run_command_with_job_id`
- `converter::run_ffmpeg_with_progress`
- `commands::hidden_command`
- `tools::get_tool_path` (PATH scanning)
- the `RUNNING_PROCESSES`, `CANCELLED_JOBS` and `TOOL_PATHS` globals

The same goes for `process::run` and `run_with_timeout`, which do not drain their pipes.

```rust
// NEW — sketch of the contract, not code to be written now

    pub engine: EngineId,               // allowlisted identity; no free-form program
    pub args: Vec<Arg>,                 // see E.3

    pub env: EnvPolicy,                 // E.4

    pub stdout: Capture,                // Discard | Tail(n) | Collect(cap)   (cap default 8 MiB as today)
    pub stderr: Capture,                // + optional line callback for progress parsing
    pub on_stderr_line: Option<&'a (dyn Fn(&str) + Sync)>,
    pub limits: ExecLimits,             // wall timeout, memory, process count, output-bytes, priority
    pub cancel: &'a CancelToken,
}
```

### E.2 Executable allowlisting
- An executable is **only** reachable through `EngineId`. That enum already exists, with `Office, Ffmpeg, Ffprobe, Tesseract, Speech, AudioFfmpeg, AudioFfprobe`; Ghostscript and Pandoc are added if kept.
- `resolver::resolve` keeps the bundled tier only: `<ENGINES_ROOT>/<engine dir>/<relative exe>`.
  - `ENGINES_ROOT` comes from the server config file, not from requests and not from environment variables.
  - The **system tier is removed** for the server, including `LOCALCONVERT_ALLOW_SYSTEM_OFFICE_FALLBACK` and `tools::get_common_paths`.
- **Startup verification** reuses the existing manifest checkers (`office_manifest::self_check`, `ffmpeg_manifest::check_dir`, `speech_manifest::check_dir`). They check SHA-256 hashes, pinned version and architecture. An engine that fails becomes `ENGINE_MISSING` in capabilities and is never spawned.
- **At spawn:** the executable's size and modification time are compared with the values recorded at verification. A mismatch is refused, so a binary swapped while the server runs is caught without re-hashing gigabytes on every spawn.

### E.3 Argument construction
```rust
pub enum Arg { Flag(&'static str), Value(String), Input(RelPath), Output(RelPath) }
```
- `Flag` values are compile-time literals.
- `Value` is validated against a per-engine checker: numeric ranges, enum names such as LibreOffice filters (`"pdf"`, `"docx"` …) and FFmpeg codecs from a fixed table. No value may start with `-` unless it comes from a numeric formatter.
- `Input` and `Output` are **relative** paths inside the job directory, built by the server (`in/source.docx`, `work/out.pdf`). They therefore can never begin with `-`, which removes option injection through filenames. Where an engine supports it, `--` is inserted before positional paths.
- The free-form `customFfmpegParams` setting has no representation at all.

### E.4 Environment control
- `env_clear()`, then an explicit allowlist:
  - `PATH` = the engine's own `bin/` directory plus the OS system directories (Windows: `%SystemRoot%\System32`, needed for DLL loading)
  - `TEMP`, `TMP`, `TMPDIR` = `<job>/work/tmp`
  - `HOME`, `USERPROFILE` = `<job>/work/home` (LibreOffice and fontconfig write here)
  - `LANG=C.UTF-8` (Linux)
  - `SystemRoot` (Windows)
- This supersedes the existing `ENV_DENYLIST` (deny-by-name) with allow-by-name. The variables on that denylist (`GGML_BACKEND_PATH`, `FFREPORT`, `TESSDATA_PREFIX`, `MAGICK_*`, `GS_LIB`, `FONTCONFIG_PATH`, `PYTHONPATH`) are now absent by construction.

### E.5 Working directory, stdin, stdout and stderr
- **cwd** is always `<job>/work` (a typed `WorkDir`, unchanged from the current invariant).
- **stdin** is `Stdio::null()` by default. FFmpeg additionally gets `-nostdin`, as `audio_prep` already does. This also prevents prompts (password-protected archives, LibreOffice dialogs) from hanging a job.
- **stdout and stderr** are always drained on threads (the `run_cancellable` pattern). stdout is collected with a cap; stderr keeps only the 64 KiB tail (`STDERR_TAIL_CAP`) plus the line callback for progress.
- stderr goes **only** into the internal `technical_detail` field. It is never returned to users and never logged at info level (§S).

### E.6 Timeouts, cancellation and process trees
**Polling.** The loop polls at 50 ms. It checks, in order: exit, cancel token, wall timeout, memory/process limits (Windows Job Object accounting or Linux cgroup), and output-bytes growth in `work/`.

**Windows (pilot) — Job Object per spawn:**
- The child is created with `CREATE_SUSPENDED | CREATE_NO_WINDOW | BELOW_NORMAL_PRIORITY_CLASS`.
- It is assigned to a new Job Object before being resumed. This needs **NEW** use of the `windows-sys` crate (`CreateJobObjectW`, `SetInformationJobObject`, `AssignProcessToJobObject`, `ResumeThread`). Note that `std::process::Command` cannot create suspended processes, so this needs a small platform module.
- Job Object limits:
  - `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` — every descendant dies with the handle, including LibreOffice's launcher → `soffice.bin` chain. This is the residual risk documented in `process.rs` and `docs/OFFICE_ENGINE.md`.
  - `JOB_OBJECT_LIMIT_JOB_MEMORY` — the memory cap.
  - `JOB_OBJECT_LIMIT_ACTIVE_PROCESS` — process-count cap (FFmpeg/whisper 1–2, LibreOffice 8).
  - `JOB_OBJECT_LIMIT_DIE_ON_UNHANDLED_EXCEPTION` — no WER dialogs hanging.
- Cancel or timeout calls `TerminateJobObject` and waits.

**Linux (later):**
- `pre_exec`: `setsid()`, `setrlimit(RLIMIT_AS, mem)`, `RLIMIT_FSIZE` (the kernel enforces the output cap), `RLIMIT_NPROC` and `RLIMIT_CORE=0`, plus `prctl(PR_SET_PDEATHSIG, SIGKILL)`.
- Cancel sends `kill(-pgid, SIGKILL)`.
- With a container or systemd deployment, cgroup v2 (`MemoryMax`, `TasksMax`, `CPUQuota`) is set on the service. Per-job cgroups are optional.
- Network isolation via `unshare(CLONE_NEWNET)` or the container's `--network none` for the engine sandbox.

### E.7 Exit-status validation
Success requires **all** of these:
1. `ExecEnd::Success` (exit code 0).
2. The expected output path exists, is a regular file, is not a link, and lies inside `work/`.
3. The size is greater than 0 and no more than `max_output_bytes` (§I).
4. The sniffed type matches the requested format (§H.4).

LibreOffice can exit with code 0 without producing a file; `office::convert` already checks the expected file exists, and this is generalised. Non-zero exits map to `<ENGINE>_FAILED`, timeouts to `<ENGINE>_TIMEOUT` (as with the existing `OFFICE_TIMEOUT`), and limit hits to `RESOURCE_LIMIT`.

## F. MULTI-USER SECURITY

### F.1 Mechanism
1. **Identity comes only from authentication.** The `AuthenticatedUser` extractor (§J) runs before routing to any `/api` handler. No request field — body, query, header or path — can name an owner. Records have no "owner" input field at all.
2. **Owner-scoped store API.** The job/file stores (**NEW** `jobs::store`, `storage::files`) expose **no** unscoped lookup to the `api` module:
   ```rust
   impl JobStore {
       pub fn get_owned(&self, who: &AuthenticatedUser, id: JobId) -> Result<OwnedJob, NotFound>;
       // OwnedJob has a private constructor: the only way to hold one is via get_owned().
   }
   ```
   Every operation (`cancel`, `retry`, `download`, `delete`, `events`) takes an `OwnedJob`, so an unchecked call does not compile. Unscoped iteration (janitor, metrics, shutdown) lives in `pub(crate)` functions not exported to `api`.
3. **The check:** `record.owner.tenant_id == who.tenant_id && record.owner.user_id == who.user_id`. Both values are compared exactly (no case folding), using the values from the authenticator.
4. **Uniform 404.** A foreign ID returns exactly what an unknown ID returns. There is no 403 that would confirm existence.
5. **Physical defence in depth.** File paths are derived from `record.owner.user_key` and the record's own ID, never from the requester. So even a logic bug in a handler that fetched the wrong record would still need that record's owner to match before any path is built.
6. **Events.** The per-user SSE stream subscribes to a channel keyed by `user_key`. The per-job stream first goes through `get_owned`. Events are published only to the owner's channel.
7. **Admin role.** Admins get aggregate metrics and capability diagnostics. They get **no** API access to other users' files, jobs or transcripts. Server operators keep OS-level access, which is a policy and audit matter (§S).

### F.2 What User A cannot do to User B
| Action by A on B's resource | Blocked by |
|---|---|
| Read B's file metadata (`GET /files/:id`) | `get_owned` → 404 |
| Use B's `file_id` in `POST /jobs` | File lookup is `get_owned` → 404 `FILE_NOT_FOUND` |
| Download B's result (`/download`, `/transcript`) | `get_owned` → 404 |
| Cancel B's job | `get_owned` → 404. Additionally, cancel tokens are never looked up by raw ID, unlike `converter::kill_process`/`CANCELLED_JOBS` today |
| Retry B's job | `get_owned` → 404 |
| Inspect B's status (`GET /jobs/:id`, `/events`) | `get_owned` → 404. Not subscribed to B's channel |
| Guess IDs | 122 random bits per UUIDv4, plus per-user rate limits on 404s (§I) |
| Reach B's files on disk via path tricks | No request-derived paths (§D.2) |
| Exhaust shared capacity | Per-user running/queued caps, fair scheduling, quotas |

### F.3 Required tests (to be written with the server)
For every endpoint, there must be a two-user test showing that B's IDs produce byte-identical 404 responses for A. There must also be a test proving `OwnedJob` cannot be constructed outside `jobs::store`, enforced by module privacy.

## G. PROGRESS

| | Polling | SSE | WebSocket |
|---|---|---|---|
| Fits server→client progress | Adequate, but laggy or wasteful | Exactly | Yes |
| Commands (cancel/retry) | REST | REST | Could share the socket, but no need |
| Reconnect | Trivial | Built in (`EventSource` auto-reconnect, `Last-Event-ID`) | Manual |
| Proxies / corporate networks | Best | Good (plain HTTP; needs buffering off) | Often interfered with |
| Auth | Same as REST | Same cookie/proxy auth as REST | Handshake only; separate handling |
| Implementation cost | Lowest | Low (axum built-in) | Highest |

**Recommendation: SSE**, for these reasons:
- **One per-user multiplexed stream** (`GET /api/v1/events`) carries every job's events with a `job_id` field. This avoids the 6-connections-per-origin HTTP/1.1 limit with many simultaneous jobs; HTTP/2 at the proxy makes per-job streams cheap too.
- **The snapshot is authoritative.** On every (re)connect the client calls `GET /jobs/:id` for its known active jobs.
- **Fallback.** If SSE is unavailable, the client polls `GET /jobs/:id` every 2 s.

Event format:
```
id: <job_id>:<seq>
event: job
data: {"job_id":"…","seq":17,"state":"running","stage":"transcribing","progress_pct":42,"elapsed_secs":61,"eta_secs":null}

event: ping          (comment heartbeat every 15 s keeps proxies from closing the stream)
```
Terminal events include `error` (code + Turkish message) or `result` summary. The bus is a **NEW** `events::bus`: per job, a `tokio::sync::watch` holding the latest snapshot; per user, a `tokio::sync::broadcast` (capacity 256). A lagging subscriber receives a `resync` event and re-fetches snapshots, so no unbounded buffering occurs.

**Proxy requirements:** response buffering off for `/api/v1/events*` (nginx `proxy_buffering off`; IIS ARR `responseBufferLimit="0"`), read timeout above 60 s, and the server sends `Cache-Control: no-store`.

**Why not WebSocket:** nothing in this application needs client→server messages on the stream. The existing desktop model is already one-way push (`emit` of `conversion-progress` and `speech-job-update`) plus request/response commands, which is exactly SSE + REST.

## H. UPLOAD / DOWNLOAD

### H.1 Upload streaming
1. The request is authenticated and `Content-Length` is required. If it exceeds the global maximum (2 GiB) or the user's remaining quota, the server answers `413`/`429` **before reading** the body.
2. The body stream is written to `staging/<uuid>.part`, created with `create_new`, through a counting writer. If the byte count exceeds the cap, the upload is aborted and the part file deleted.
3. **Early sniff.** After the first 64 KiB, the type family is decided (§H.3) and the **category cap** is applied from then on (e.g. image 50 MiB). An oversized image does not have to upload 2 GiB to be rejected.
4. **Timeouts.** A minimum-throughput guard aborts an upload averaging under 10 KiB/s over 60 s, which defends against slowloris. The proxy also has request-body timeouts.
5. When the stream completes:
   1. Validation (§H.2).
   2. Atomic rename into `users/<key>/files/<file_id>/blob`.
   3. Quota accounting.
   4. The `FileRecord` is created and `201` returned.

**Why a raw body instead of multipart:** one file per request, no multipart parser state machine, no boundary edge cases, and upload progress is trivial with `XMLHttpRequest.upload.onprogress`. A batch is N parallel uploads, limited client-side to 3 concurrent.

### H.2 Validation timing
| When | Check |
|---|---|
| Headers | Auth, `Content-Length`, quota, name header present and ≤ 255 chars after decoding |
| First 64 KiB | Magic-byte family, extension allowlist, extension ↔ family agreement, category cap |
| End of stream | Full structural check per family:<br>• image: `native::image` header decode with dimension caps (no full decode)<br>• PDF: `%PDF-` header, `%%EOF` near the tail, page count via `lopdf` with a cap<br>• OOXML/ODF: ZIP central directory plus required part (`[Content_Types].xml`/`mimetype`), entry-count and expansion check (§O limits)<br>• audio/video: `ffprobe` with a 30 s timeout, duration check (`SpeechLimits::check_duration` for audio)<br>• text/CSV/MD: valid UTF-8 (or a declared Turkish 8-bit encoding), ≤ category cap |
| Job start | Matrix and capability check |
| After engine | Output validation (§H.4) |

### H.3 MIME, extension and name handling
- **Client `Content-Type` is ignored** for every decision; it is not even stored.
- **The type is decided by the server:** magic bytes (**NEW** `formats::sniff`, a small in-house table covering the supported families, so no new dependency is strictly needed), then container inspection:
  - ZIP → OOXML vs ODF vs plain ZIP, by required entries
  - OLE CFB → DOC/XLS/PPT, by stream names
  - `ftyp` brand → MP4/M4A/MOV
  - EBML → WebM/MKV
  - `OggS` → Ogg
- **Extension.** It is lower-cased and taken after the last dot of the decoded display name. It must be in the allowlist **and** consistent with the sniffed family (for example, `.docx` must sniff as OOXML-Word). Mismatch → `422 FILE_TYPE_MISMATCH`. Extension-less files are accepted only when the sniff is unambiguous, and the server assigns the extension.
- **Display name.** Percent-decoded and NFC-normalised. Control characters, `/ \ : * ? " < > |` and leading dots are removed, and length is capped at 255. It is stored only in memory, used only for display and the download name, and never as a path. Turkish characters are preserved.

### H.4 Output validation (before publishing to `out/`)
Regular file inside `work/`, size within limits, sniffed type equal to the requested format, then an atomic rename to `out/result.<ext>`. A failure here becomes `failed / OUTPUT_INVALID`, the existing `EngineError::output_invalid` vocabulary.

### H.5 Download
- **Authorisation:** `get_owned` + `state == completed` + not expired.
- **Headers:**
  ```
  Content-Type: <from server table for the output format>      (never sniffed from content at serve time)
  Content-Disposition: attachment; filename="<ASCII fallback>"; filename*=UTF-8''<percent-encoded name>
  X-Content-Type-Options: nosniff
  Content-Security-Policy: sandbox; default-src 'none'
  Cache-Control: no-store
  Content-Length: <size>
  ```
- **Download name:** `<display stem>.<target ext>`, e.g. `Rapor_2026.docx` → `Rapor_2026.pdf`; the same-format case adds `_donusturuldu`. The ASCII fallback transliterates Turkish letters (`ç→c, ğ→g, ı→i, İ→I, ö→o, ş→s, ü→u`) and replaces everything else with `_`. CR/LF and quotes are always stripped, so header injection is impossible.
- **Inline display:** HTML/SVG outputs are **never** served inline (always `attachment`). Image previews in the UI use the browser's local `File` object before upload (§M), not server responses.
- **Range requests:** not supported in v1 (not needed).

## J. AUTHENTICATION BOUNDARY

### J.1 Types (NEW, `meb-server::auth`)
```rust
pub struct AuthenticatedUser {

#[async_trait]
pub trait Authenticator: Send + Sync {

```
- An axum extractor calls the configured `Authenticator`. The conversion core (`meb-core`) never sees this type; it only receives an `OwnerRef` and a `JobContext`.
- Changing the identity provider therefore touches `auth/providers/*` and configuration only.

### J.2 Providers
| Provider | v1? | Behaviour |
|---|---|---|
| `DevLocal` | Yes, dev only | Fixed user. Refuses to start unless bound to `127.0.0.1` and `mode = "development"` |
| `TrustedProxy` | **Yes, first production provider** | Reads configured headers (default `X-Remote-User`, `X-Remote-Tenant`, `X-Remote-Roles`). Accepts them **only** when the TCP peer is in `trusted_proxies` (exact IPs/CIDRs); otherwise `401`. The proxy must strip these headers from client requests. Optional shared-secret header or mTLS between proxy and server. This works with any SSO the proxy speaks: OIDC, SAML, Kerberos/AD (IIS Windows Authentication), LDAP |
| `Oidc` | Later | Authorisation-code + PKCE in the server, `HttpOnly; Secure; SameSite=Lax` session cookie. Only if no proxy-level SSO is available |
| `Saml` | Via proxy | Rust SAML libraries are less mature; terminate at the proxy/IdP gateway |
| `Ldap` | Via proxy, or later | Avoid the server handling passwords; prefer Kerberos/AD at the proxy |

**Why TrustedProxy first:** the repository contains no evidence of any particular MEB identity system (Audit §9). The trusted-proxy contract is the one integration that works with all of them, keeps credentials out of the conversion server, and leaves TLS where it belongs.

**Risk:** header spoofing if the server is reachable without going through the proxy. Mitigations:
- Bind to localhost or an internal interface only.
- Enforce `trusted_proxies`.
- Firewall the port.
- Optionally use mTLS.

### J.3 Roles and tenancy
- `Role::User` can use all endpoints for their own resources.
- `Role::Admin` can additionally use `/api/v1/admin/*` (NEW, later): capability diagnostics, aggregate metrics and engine self-check. It cannot access other users' content.
- `tenant_id` is part of `OwnerRef` and of `user_key`. A single-tenant deployment uses one fixed tenant from config.
- Per-tenant quotas and capability policy (`DISABLED_BY_POLICY`) are supported by the model but not configured in v1.

## K. SES DİKTE

### K.1 Uploaded audio file
1. `POST /files` with `X-Upload-Purpose: speech`.
   - Allowlist: `wav mp3 m4a aac flac ogg` (existing `audio_prep::ACCEPTED_EXTENSIONS`) plus `opus webm`.
   - Server sniffing confirms the container.
   - `ffprobe` duration is checked against `SpeechLimits::check_duration`.
2. `POST /jobs { kind: "speech_transcribe", file_id, options: { language } }`. The language must be in the speech manifest's `languages`.
3. The worker:
   1. Hard-links `blob` to `jobs/<id>/in/input.<ext>`.
   2. Calls `speech::pipeline::run_file_job_in`, adapted to take the staged relative input instead of a user path. `validate_source` shrinks to an extension and size re-check, because UNC/URL checks become meaningless.
   3. Runs normalisation (`audio_prep::normalize` → 16 kHz mono PCM16 `norm.wav`), the exact-duration check, the silence gate (`analyze_energy`), then `WhisperCppEngine::transcribe`. All of this is unchanged.
4. Output: `transcript.json` (the `TranscriptDto` shape) is written to `out/`. `norm.wav` and the whisper JSON are purged with `work/`.

### K.2 Browser microphone
**Recording.** It needs a secure context: `getUserMedia` requires HTTPS (or `localhost`), so the deployment must use TLS with a certificate the client machines trust (§R). The flow:
1. Permission is requested **only** when the user clicks "Kaydı başlat". The existing rule — loading the page never activates the mic — is preserved.
2. `MediaRecorder` records with the first supported type from this order: `audio/webm;codecs=opus` → `audio/ogg;codecs=opus` → `audio/mp4`. Feature detection uses `MediaRecorder.isTypeSupported`. **Assumption:** Chromium-based browsers (Chrome, Edge — the likely institutional default) produce WebM/Opus, Firefox produces Ogg/Opus or WebM/Opus, and Safari produces MP4/AAC. The code must not hard-code a browser→format mapping; it relies on `isTypeSupported`.
3. A client timer shows elapsed time and enforces the 2 h limit (`max_recording_secs`). Chunks are collected with `timeslice = 1000 ms`.
4. On stop, tracks are stopped (the mic indicator turns off), the chunks are assembled into a `Blob`, and it is uploaded with `X-Upload-Purpose: speech_recording` and a server-chosen name. The server derives `recording.<ext>` from the sniffed container.
5. The speech job then follows exactly the uploaded-file path.

**Required build change (decision, implemented later):** the bundled minimal FFmpeg (`scripts/ffmpeg/build-ffmpeg.sh`) currently enables the demuxers `wav, mp3, aac, mov, flac, ogg` and the decoders including `opus` and `aac`.
- **There is no Matroska/WebM demuxer**, so Chromium recordings would fail normalisation today. Add `--enable-demuxer=matroska`; this is LGPL, part of FFmpeg, and the build stays audio-only and LGPL.
- Ogg/Opus (Firefox) and MP4/AAC (Safari, via `mov`) already work with the current build.
- Alternative considered: encoding WAV in the browser with an AudioWorklet. It sidesteps the demuxer but means 16× larger uploads and more client code. Rejected for v1.

**Live (streaming) dictation is out of scope.** `whisper-cli` is batch-only. Record-then-transcribe matches the current file UX.

### K.3 Cancellation, cleanup, timestamps and retrieval
- **Cancel:**
  - During recording: the client discards the chunks; nothing is sent.
  - During upload: XHR `abort()`; the server deletes the `.part` file.
  - During the job: `POST /jobs/:id/cancel` → `CancelToken` → `run_cancellable` kills whisper or FFmpeg → `cancelled`. Unmounting the page still cancels a running job, keeping the `useSpeechJob` rule.
- **Temp cleanup:** `work/` (normalised WAV, whisper JSON, model link if any) is purged at the end of the job. The upload `blob` (the recording) is deleted when the job reaches a terminal state, if the purpose is `speech_recording`, so recordings are not kept for retry by default. For uploaded files, retention follows `upload_ttl` to allow retry.
- **Timestamps:** segment-level `start_ms`/`end_ms` from whisper `-oj`, with the existing `timestamps_available` flag. No word-level timestamps.
- **Retrieval:** `GET /jobs/:id/transcript` (JSON for the UI) and `GET /jobs/:id/download?format=txt|srt|vtt|json`. SRT/VTT are rendered from segments on demand. Transcript text is never logged.
- **CPU:** one speech permit with `min(8, cores/2)` threads. The UI shows the queue position from the snapshot ("Sırada: 2").

## N. PDF→DOCX

### N.1 Facts from the repository (Audit §14)
- PDF→DOCX/ODT/RTF/HTML/TXT/EPUB is `reconstruction::PdfToDocx::convert` → `engines::office::convert(..., use_pdf_import_filter = true)`, i.e. LibreOffice `--infilter=writer_pdf_import --convert-to docx`. There is no Rust reconstruction and no post-processing.
- `ReconstructionQuality::Partial` exists but is unused. PDF is absent from `capabilityGating.ts::OFFICE_EXTENSIONS`, so the feature is ungated in the UI.
- The importer emits positioned text frames per text run and line/rectangle shapes per table rule. That explains thousands of objects on a 21-page landscape table document.

### N.2 Options compared
| Criterion | A. Keep LibreOffice importer | B. Mature server-side PDF→DOCX engine | C. Hybrid semantic reconstruction |
|---|---|---|---|
| Table fidelity | **Poor**: tables become frames and lines; not editable as tables | Varies by product: commercial SDKs are good on ruled tables; open-source tools are mixed on merged and borderless cells | **Best achievable for the target corpus**: explicit table model (ruling-line + text-alignment detection) with validation; falls back when confidence is low |
| Turkish text | Depends on the PDF's ToUnicode maps; frame-per-run keeps glyphs but breaks words across frames | Depends on the engine's CMap/ToUnicode handling; must be tested with `ç ğ ı İ ö ş ü` | Full control: explicit ToUnicode/CMap handling, a dotted/dotless-i check, and a Turkish character-coverage metric |
| Layout | Visually close, structurally useless (absolute frames) | Mostly flow with some anchored objects | Flow text for body and real tables; anchored only for figures; landscape sections preserved |
| Offline | Yes | Yes only if self-hosted; **cloud-API products are excluded** | Yes |
| Privacy | In-process on server | Self-hosted only; vendor telemetry/licence call-home must be disabled or ruled out | In-process |
| Resource cost | LibreOffice cold start, 0.3–2 GB, up to 600 s | Moderate (often Python/.NET/Java runtimes) | Moderate CPU, low memory; no LibreOffice for the common path |
| Licensing | MPL-2.0 (already shipped; notices in `THIRD_PARTY_NOTICES/LibreOffice`) | **The main risk.** PyMuPDF-based tools inherit **AGPL-3.0** (or a commercial licence); AGPL §13 can create source-offer obligations for network use. Commercial SDKs have per-server cost and vendor lock-in | Depends on parts: candidate pieces (a PDF parser such as `lopdf` (MIT, already used) or pdfium (BSD-3); a DOCX writer) can be permissive |
| Maintainability | Nothing to maintain, nothing to improve | External dependency to track | Highest engineering effort; owned code |

### N.3 Recommendation (architecture only)
1. **Introduce a slot now.** Add a `PdfToDocxEngine` trait in `meb-core::pdf`, generalising the existing `PdfToDocx` struct, with implementations selected by config. Add a separate capability `pdf_to_docx` with a quality tier (`BASIC` | `SEMANTIC`), exposed in `/capabilities` and shown in the UI. This fixes the ungated state.
2. **v1 ships A**, explicitly labelled *"Deneysel — tablolu belgelerde düzen bozulabilir"*. It runs in the `office` class with the 600 s timeout.
3. **Evaluation before choosing B vs C.** Build a private corpus of real MEB PDFs, starting with the 21-page landscape table document; it is not committed to the public repo. Score on:
   - table cell accuracy
   - text coverage (characters recovered / characters present)
   - Turkish character fidelity
   - DOCX object count
   - open time in Word
   - wall time and peak memory

   Screen B candidates by licence **before** evaluating them; AGPL candidates need a legal decision (§T).
4. **Target architecture is C.** The semantic pipeline runs out-of-process through `exec` as its own `EngineId`, either a Rust helper binary or a vetted tool. Its outputs:
   - an intermediate document model (pages → blocks → paragraphs/tables/cells → runs with fonts)
   - a DOCX writer
   - a confidence score
   - **automatic fallback to A** when confidence is below threshold, with the tier reported in the result

   B can be plugged into the same slot if the evaluation shows a licensable B is good enough, which saves building C.

**Risks:** C is real engineering work (layout analysis is a long-tail problem), and the corpus may contain scanned PDFs, which need OCR (future). For those the capability must say "metin katmanı yok" rather than produce garbage.

## O. ARCHIVE

### O.1 Scope decision for v1
| Function | v1 |
|---|---|
| ZIP extract (as conversion input, e.g. ZIP → TAR.GZ) | **No.** Archive *conversion* is dropped from v1; its user value is low and its risk is the highest (Audit C4) |
| ZIP create (bundle a user's completed outputs for one download) | **Yes** — `archive_bundle` job, inputs are server-produced files only |
| OOXML/ODF container inspection (they are ZIPs) | **Yes** — read-only, limits applied (§H.2) |
| 7-Zip (7z/RAR/etc.) | **Removed** from the server. If needed later: re-add via `exec` with the limits below and a pre-scan listing |
| tar / tar.gz | Later, via pure-Rust `tar` + `flate2` (NEW deps) under the same extractor contract |

### O.2 Safe extractor contract (NEW `meb-core::archive`, replaces `native/archive_zip.rs`)
- **Pre-scan** of the central directory: entry count ≤ 10 000, declared sizes summed ≤ 2 GiB, no encrypted entries (rejected; also prevents password prompts). The ZIP64 sanity check is that the declared counts agree with the directory.
- **Per entry:**
  - Name: `enclosed_name()` (kept from the current code) **plus**: no absolute paths or drive prefixes, no `..`, no NUL/control characters, depth ≤ 32, total length ≤ 240, each component passed through `sanitize_filename_component` (kept; it also rejects Windows reserved names).
  - Case-insensitive duplicate detection, because `A.txt` and `a.txt` collide on NTFS.
  - **Type:** regular files and directories only. Entries whose Unix mode is a symlink (`S_IFLNK` in external attributes), a device or a FIFO are rejected. Hard links do not exist in ZIP; for tar later, `Link`/`Symlink`/char/block/fifo entries are rejected.
- **Writes:**
  - Into `work/x/` only, via `create_new` — no overwrite, no following.
  - Through a counting writer that enforces **actual** bytes: entry ≤ 1 GiB, running total ≤ 2 GiB, actual-bytes / compressed-bytes ≤ 100 per entry and overall. Declared sizes in headers are never trusted for enforcement.
- **Nested archives** are extracted as plain files, never recursively.
- **Cancellation and timeouts:** the cancel token is checked per entry and every 1 MiB written. A 300 s wall-time cap is enforced by the worker.
- **Disk:** the pre-flight quota check uses min(declared total, 2 GiB), and the free-space watermark is re-checked every 100 MiB.

### O.3 Writer (bundle)
Streaming `std::io::copy` per file. This replaces `create_zip`'s `read_to_end` into memory. Inputs come only from the same user's `out/` files. The bundle size cap is the per-user quota, and entry names use download naming (§H.5).

### O.4 7-Zip (only if a later decision re-adds it)
Run through `exec` with `x -bd` (no `-y`), with `-o` pointing into `work/x/` and stdin null. Link-handling switches must be chosen and tested against the pinned 7-Zip version; that has not been verified in this proposal. Before extraction, run `l -slt` and parse it to enforce count and size limits. Job Object/rlimit memory and `RLIMIT_FSIZE`-style output monitoring apply. After extraction, re-walk the tree and reject any non-regular file. **RAR** is not supported (licensing/unRAR).

## P. FUTURE SAS (architecture only; nothing exists today)

| Format | Nature | Placement |
|---|---|---|
| **XPT** (SAS Transport v5/v8) | Published, documented exchange format | `data` engine family, **first**. An in-process Rust reader (bounded and simple), or out-of-process if a C library is used |
| **SAS7BDAT** | Proprietary dataset, reverse-engineered by the community; compression variants and encodings (including Turkish `cp1254`/`latin5`) | `data` family, **second**. The reader runs **out-of-process** through `exec` (e.g. a small helper built on ReadStat (MIT, C)), because a C parser of a proprietary format must not run inside the server process |
| **SASHDAT** | SAS Viya/CAS distributed in-memory table export | **Not supported.** Capability `sas_hdat` = `NOT_IMPLEMENTED`, with guidance to export from CAS to CSV/Parquet/SAS7BDAT on the SAS side. No standalone offline parser is assumed |
| `.sas` program files | Code, not data | Never executed. At most treated as plain text |

**Engine shape** (NEW, later): `meb-core::data` with
- `trait DatasetReader { fn schema(&mut self) -> Schema; fn next_batch(&mut self, max_rows) -> Option<Batch>; }`
- `trait DatasetWriter { csv | xlsx | parquet }`

The data streams batch by batch; it is never fully materialised.

- **Job kind:** `data_convert` in class `data` (1–2 permits).
- **Limits:** rows (XLSX hard limit 1 048 576 rows, which must produce a clear `DATA_TOO_MANY_ROWS`), columns, output size, wall time.
- **Metadata:** variable labels/formats go to a header row or a sidecar sheet, by product decision.
- **Encoding** is detected from file metadata, with an override option.
- **Licences:** permissive readers and writers only; no SAS software is embedded.

## Q. FUTURE IMAGE OPTIMISATION (architecture only)

- **Job kind:** `image_optimize` (separate from `convert`) in class `light`, capability `image_optimization`.
- **Pipeline:** `native::image` decode (existing limits) → optional resize (`transform.rs`, existing) → EXIF orientation applied → metadata strip (existing default) → encode with a per-format encoder → **keep the smaller of original and result** (never return a larger file; report `not_reduced` instead).
- **Encoders** (NEW dependencies, licence-vetted):
  - JPEG: quality and progressive (current `image` encoder, later a mozjpeg-class encoder via `exec`)
  - PNG: lossless optimisation (an oxipng-class pure-Rust optimiser)
  - **WebP lossy:** needs libwebp-class bindings. The current `image` build's WebP encoder is lossless only
  - **AVIF:** a rav1e/ravif-class encoder, CPU-heavy → its own `media`-like permit and timeout
- **Options:** `quality` (1–100, default 82), `max_width`/`max_height`, `format: keep|webp|avif|jpeg|png`, `strip_metadata` (default true).
- **Result:** `{ input_bytes, output_bytes, saved_pct, width, height, format }` in the job `result`; the comparison view reuses `ImageComparePreview.tsx` with the local original and the downloaded result.
- **Batch:** N jobs plus an optional `archive_bundle`. Per-user caps apply. Batch priority is below interactive single jobs (scheduler hint).

## R. DEPLOYMENT

### R.1 Consequences of each option, given the repository today
| Option | What works immediately | What must be built | Consequences |
|---|---|---|---|
| **Windows Server** (2019/2022+) | All pinned engines and their verification (LibreOffice 25.8.7 x86-64 MSI admin image; whisper.cpp v1.9.2 Windows binaries + `ggml-small-q5_1`; minimal LGPL FFmpeg 9.0.2 built with MSYS2), the PowerShell prep/verify scripts and the manifests. **Microsoft core fonts (Times New Roman, Arial, Calibri) are present natively**, which materially helps LibreOffice fidelity for MEB Office documents | Windows service host, Job Object executor backend, NTFS ACL setup, Windows Firewall outbound rules per engine exe, and a reverse proxy | Fastest path to a working, verifiable pilot. Weaker sandboxing primitives than Linux (no namespaces/seccomp; AppContainer is complex). Ops follows Windows patching. Full-featured video still needs a separate FFmpeg build decision |
| **Linux** (bare VM) | Rust server, native image, and the `build-ffmpeg.sh` script (bash; adaptable from MSYS2 to Linux) | Linux LibreOffice acquisition and a new manifest/self-check (TDF `.deb`/`.rpm` or distro packages), a Linux whisper.cpp build plus manifest, Linux `free_disk_bytes`, the `unix` executor backend, and **font provisioning** (metric-compatible Liberation/Carlito/Caladea; MS fonts have licensing constraints) | Best isolation (namespaces, cgroups, seccomp, `noexec` mounts). Adds an engine-porting phase before any LibreOffice/speech slice works. Office rendering differences until fonts are sorted |
| **Docker** | (Linux containers) same as Linux | Same as Linux, plus images and an orchestration choice | Reproducible pinned engines and the easiest network isolation for engines (`--network none` in an engine sandbox). **Windows containers for LibreOffice are impractical** (large servercore images, poorly trodden), so Docker effectively implies the Linux port |
| **Reverse proxy** | (component, not an alternative) | Config: TLS, auth/SSO, body limit, SSE buffering off, security headers | **Required in every option** for TLS (microphone needs HTTPS) and the trusted-proxy auth provider |

### R.2 Recommendation
**Initial deployment: Windows Server pilot, a single instance, behind the organisation's reverse proxy.**
- `meb-server` runs as a Windows service under a virtual account (`NT SERVICE\MebDonustur`), bound to `127.0.0.1` or an internal interface only.
- `ENGINES_ROOT` holds the existing verified bundles (read-only ACL). `DATA_ROOT` is on a dedicated NTFS volume with the ACLs from §D.3.
- **Windows Firewall:** outbound **block** rules for every engine executable (`soffice.exe`, `soffice.bin`, `ffmpeg.exe`, `ffprobe.exe`, `whisper-cli.exe`). The server executable may reach only the configured proxy/IdP if needed. This enforces "no unnecessary outbound network access" at the OS level, not just by the absence of code.
- **Reverse proxy:**
  - If the institution has a standard (IIS + ARR with Windows Authentication, or an existing gateway), use it. The required settings are listed above.
  - If not, the reference configuration is **Caddy**: a single binary that runs on Windows, uses HTTP/2, supports an internal CA, and has simple header rules.
- **Hardware assumption:** a CPU with **AVX2** (whisper measured 0.24× real time with AVX2 vs 2.0× slower than real time on an SSE4.2-only build, per `docs/SPEECH_ENGINE.md`). The startup self-check reports this through the existing `SPEECH_CPU_UNSUPPORTED` path.

**Why:** it is the only option where every existing engine, manifest, hash and verification script is usable without a porting phase. The first vertical slices (image, Office→PDF, speech) can therefore be validated on real hardware early. The executor's platform backend is the isolation point, so moving to Linux/containers later (recommended for production hardening if MEB IT supports Linux) means writing `exec/unix.rs` plus Linux engine manifests — not redesigning.

**Risks:**
- Weaker per-job isolation on Windows. Mitigated by the low-privilege service account, Job Objects, firewall rules, macro-disabled LibreOffice profiles and patch discipline.
- Windows-only CI drift. Mitigated by building `meb-core` and `meb-server` on Linux in CI from day one, even before Linux engines exist.

## T. ARCHITECTURAL DECISIONS

### Decisions required before coding
Only items this proposal cannot settle from the repository:

1. **Confirm the pilot platform.** Windows Server plus the target hardware: core count, RAM, **AVX2 support**, and a dedicated data volume. The proposal recommends Windows; MEB IT must confirm it is allowed and provisioned.
2. **Reverse proxy and identity source.** Which proxy fronts the service, and which identity it can assert (AD/Kerberos, OIDC, SAML). This fills in the `TrustedProxy` header names and `trusted_proxies`. A TLS certificate trusted by client machines is required (microphone).
3. **Retention and logging policy approval (KVKK/legal).** Confirm or adjust the defaults: 60 min outputs, delete-after-download, 14-day pseudonymous logs, no client IPs.
4. **Video conversion scope in v1.** The bundled FFmpeg is audio-only and LGPL. Video needs either a separate full FFmpeg build with an explicit codec/licence choice (H.264/AAC encoders have GPL or patent implications; VP9/AV1/Opus are royalty-free alternatives), or video is deferred. *Recommended: defer video to after v1 unless a codec decision is made.*
5. **PDF→DOCX licence stance.** Whether AGPL or commercial components are acceptable candidates for option B. This is needed before the evaluation in §N.3 starts.
6. **Desktop app retirement.** This proposal assumes the Tauri app is frozen at the current checkpoint and not maintained in parallel. That needs explicit approval because it drives §M's "no dual backend".
7. **ImageMagick-dependent formats** (AVIF/HEIC/PSD/SVG input) in v1. *Recommended: excluded* (no ImageMagick on the server); they return as replacement engines in a later phase.

Everything else in this document is a concrete initial choice and does not block implementation.
